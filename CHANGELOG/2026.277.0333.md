# 2026.277.0333 — fix(deps)!: consume the sdk#313 schema-versioning removal (deploy:android's stale gate)

## Summary

Consume the **`sdk#313`** config/schema-versioning removal in `plugin-adb`, the **`deploy:android`** provider. This plugin pinned `sdk v0.2026266.623`, which predates `sdk#313` (merged 2026-09-27), so its compiled-in `loaderkit` still ran the **deleted** `GateSchemaVersion` and rejected a versionless project while resolving a `kind:android` entity:

```
deploy "device": resolving kind:android device "pixel9a-36":
  resolve kind:android entity "pixel9a-36": /tmp/opencode/dc-origin/charly.yml:
  schema 2026.261.1747 is required (found ""). Run: charly migrate
```

This blocked **every** `target: android` deploy / `kind:android` bed. It was masked in earlier R10 runs that died at an earlier step, and surfaced once the `spec#188` typed-`ExtraCandyRef` decode was fixed.

**Fix:**
- bump `sdk v0.2026266.623 → v0.2026276.1822` and `spec v0.2026266.545 → v0.2026276.1636` (both post-`sdk#313`, so `GateSchemaVersion` is gone);
- thread `ctx` through `resolveAndroidDevice` and `deploykit.ResolveContainer` — the `sdk#288` ctx requirement the bump surfaces.

Same class as the closed `opencharly/plugin-deploy-vm#32` ("its prepare-venue still enforces the deleted gate").

Closes #15.
