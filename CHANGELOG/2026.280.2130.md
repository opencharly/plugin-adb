## Summary

Every plugin's `candy/plugin-*/schema/*.cue` header tells its reader how the Go params struct is
generated. This one said it is "(driven by `task cue:gen`, which wraps this with `package params` +
`@go(params)`)" — an **umbrella Taskfile target that no longer exists**. The name is not dead in
one place: it is the same sentence in 34 plugin repos, and it is published, because
`charly docs generate` renders each plugin's `schema/*.cue` into
`docs/src/content/docs/reference/plugin/<plugin>/plugin-*.md`.

**The issue's prescribed replacement is itself false, so this PR does not apply it.** `plugin-adb#10`
says the comment "should read `charly task cue-gen` — the spec repo's task, which is what actually
drives gengotypes now". Measured inside a `plugin-adb` checkout (below): `charly task list` reports
`no tasks declared`. A plugin repo declares no `task:` entities at all, so that verb cannot drive
anything here — it is the **spec** repo's task (`spec/charly.yml` `cue-gen:` → `internal/schemagen
-mode=concat -pkg=spec` + `cue exp gengotypes` + `-mode=retag`) and it regenerates
`spec/cue_types_gen.go`. The plugin-side mechanism is the same pipeline with `-pkg=params`, run in
the plugin's own repo — which this repo's own history already records
(`CHANGELOG/2026.250.1429.md`: "params/cue_types_gen.go regenerated via the spec cue:gen pipeline
(schemagen concat -pkg=params → cue exp gengotypes → retag)") and which `/charly-internals:plugin`
states: "each plugin's `params` package is regenerated in its OWN repo by the same pipeline".

So the comment now names the mechanism that exists — `internal/schemagen -mode=concat -pkg=params`
(opencharly/spec), `cue exp gengotypes`, `-mode=retag` — and the retired target name is gone.

**No generated artifact moves with it**, and that is measured rather than assumed: the string does
not occur in this repo's committed `params/cue_types_gen.go`, so the fix cannot desync the
generated file (below). The published projection (`docs/reference/plugin/…/plugin-adb.md`) is
regenerated by the docs landing of this cutover, named under Change classification.

**This is the pattern ticket of the batch.** `plugin-adb#10` owns the sweep; the remaining 33 repos
share this one R10 story (a schema-comment rename plus, for 26 of them, its generated projection),
which is why they are one thematic batch and not a drift. The recipe is proven here before it is
repeated 33 times.
