# 2026.269.0957 — feat(plugin-adb): adopt spec 261 + fix the session-stop recorder race (atomic bed-green cutover)

## Summary

The schema-249→261 wave leg for `plugin-adb` (issue `charly#633`), **plus** the session-stop recorder race that the 261 bed exposed. Both land together because the bed that proves the pin is exactly the bed the race fails.

**1. The pin bump (the wave leg).** Bump the compiled `sdk`/`spec` pins in `candy/plugin-adb/go.mod` so a 261 charly can resolve a 261 project through this plugin (it self-loads the deploy-tree node + `kind:android` entity via `sdk/loaderkit`'s `GateSchemaVersion`, which rejects a config NEWER than its compiled spec HEAD):

| `candy/plugin-adb/go.mod` | `sdk v0.2026254.439 → v0.2026266.623`; `spec v0.2026255.1250 → v0.2026266.545`; the indirect `golang.org/x/*` bumps the new sdk/spec require |
| `candy/plugin-adb/go.sum` | the matching module-graph + zip hashes |

**2. The session-stop recorder race (`record.go` + `session_test.go`).** With the 261 gate passed, the bed's `adb-session-stop` step failed:

```
FAIL  check the adb session stop finalizes the device bracket and its evidence row  [adb-session-stop]
      adb: session: exit=1, want 0
      stderr: "/tmp/charly-session/ade-adb-session/row.json": evidence row missing after 20s (recorder never finalized)
```

`startScreenrecord`'s inner per-shot wait for the on-device capture file observed only the file, never the phase's `done` channel (the outer device-ready loop did). The runner's stop is `SIGTERM → ProcessShutdownGrace` (2 s) → `SIGKILL`; a phase that ended while the start was still inside that wait was SIGKILLed before `runSessionCapture` could finalize, so the stop gate polled a row that never appeared. The fix observes `done` in the inner wait too; on abort it returns a start error and `runSessionCapture` finalizes the (artifact-less) evidence row immediately.
