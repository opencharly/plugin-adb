# 2026.250.2106 — re-pin spec+sdk to v0.2026250.x (deploy:android preresolve wire-compat fix)

## Summary

SIX fixes on the E-4 android lane (the last added live: the row-first finalize, R1) (check-android-emulator-pod), driven by the live R10 bed:

1. **Wire-form decode fix.** The host serializes substrate plans as `spec.InstallPlanView` (the JSON-roundtrippable wire form), but the preresolve decoded them into `*deploykit.InstallPlan`, whose `Steps []spec.InstallStep` interface cannot unmarshal the wire objects — the nested android device bring-up failed exactly here:
```
deploy:android preresolve: decode params: json: cannot unmarshal object into androidPreresolveParams.plans.0.steps.0 of type spec.InstallStep
```
`androidPreresolveParams.Plans` is now `[]*spec.InstallPlanView` and `collectAndroidInstalls` re-materializes the concrete steps via `spec.PlanFromView`.

2. **Re-pin to the current spec/sdk** (v0.2026248.x → v0.2026250.x) so the plugin's linked wire types match the running host.

3. **Nested-device parent container from Deploy.MemberOf** — the in-pod device preresolve now derives `charly-check-android-emulator-pod` from the loader's MemberOf stamp (the dotted-path parse was a fallback that never fired for the bed's leaf member keys).

4. **${HOST_PORT:N} parent pod derivation shares androidParentContainer (R3)** — the endpoint device (device-net, `host: 127.0.0.1:${HOST_PORT:5037}`) wrongly reported "not nested under a pod" because the inline parse only understood dotted paths; it now uses the same MemberOf-aware derivation as the in-pod device.

5. **The adb session recorder survives a cold emulator boot AND the stop race** — the live phase can start while the Android system is still booting (device not yet attached; display/media not yet ready even once the shell answers). `startScreenrecord` retries the launch inside a bounded device-ready budget (default 90s, test-overridable) and gates on device display readiness; the device dial races the stop with a clean early finalize; and the stop chain finalizes the evidence row FIRST (row-first, `48a9364`) so a stop raced by the runner SIGTERM-grace-SIGKILL ladder can never lose the row the gate polls (the row-first invariant has its own unit test).
