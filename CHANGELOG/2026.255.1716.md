# 2026.255.1716 — refactor: land+validate the screencap artifact via sdk.LandArtifact (plan G-8)

## Summary

Migrate plugin-adb's screencap artifact handling to the shared `sdk.LandArtifact` entry point (approved plan G-8 — the last adb-side artifact producer in the R3 sweep of every capture plugin), and delete the last duplicate declaration of the `{status,message}` verb wire by moving its **decoder beside its encoder** in the contract module.

- **provider.go — the artifact tail is the shared call.** `sdk.VerbVerdict` now runs the shared exit/stdout/stderr matchers ONLY (`artifact=false`); screencap's artifact validation is the SAME `sdk.LandArtifact(ctx, nil, "", in.Artifact, &op)` call every artifact-producing capture plugin uses — the HOST leg (nil executor + blank venue path: the provider runs on the host via LocalTransport and dials the device itself, the base64 PNG comes back over the goadb exec wire, so nothing is pulled or written) — and `sdk.RunArtifactValidators` ALWAYS runs on the existing host artifact path (`artifact_min_bytes` / `artifact_min_dimensions` / `artifact_not_uniform` / `artifact_min_cast_events`). Validator failure keeps the same `adb: screencap: <err>` wire shape. A verdict gate returns BEFORE any artifact work when the shared pipeline's verdict is not `pass`.
- **provider.go — the `{status,message}` decoder now lives BESIDE its encoder (R3).** That wire has exactly one owner: `spec/ops` (`resultWire` + `ResultJSON`). The local anonymous `{Status,Message}` struct — the previous revision's `replyStatus` helper — is **DELETED**; the gate now calls **`ops.ParseResultJSON(reply)`** from `opencharly/spec#131` (merged 12:50:21Z; tag **v0.2026255.1250**, whose commit is that PR's squash-merge commit `0b3307bc`). No second declaration of the shape survives anywhere in this repo — the test helper decodes through the same shared function. `encoding/json` was ALREADY imported by `provider.go` on `main` (the op/env decode); this diff adds exactly ONE import line, `"github.com/opencharly/spec/ops"`.

Encode and decode are therefore the SAME declaration in `spec/ops`; a repo-wide grep for any surviving `{status,message}` declaration (`json:"status"` / `json:"message"`) in this plugin returns NOTHING, tests included.
