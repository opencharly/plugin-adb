## Why the proof uses a worktree-local build, and what that means for a reader

R4a/B9 asks that a documented command work with nothing but `charly` installed; **R9 requires that a change
be proven with the worktree-local, CalVer-stamped build and never a shared install.** The block asked for
the first, and the proof below uses the second — so the honest reading of the evidence is stated rather
than left to inference:

- **`./bin/charly` here is the ordinary `charly` CLI**, built from this repo's own tree because R9 forbids
  proving a change with `/usr/bin/charly`. It is not a special harness, and nothing but that binary is on
  `PATH` when it runs — **no `task`, no submodule path, no `cue`**; the verb provisions its own pinned,
  checksum-verified toolchain.
- **It reaches a plain install through the pin, and nothing else**: once `charly#873` lands,
  `v2026.281.0948` is what every subsequent build of `charly` carries, so the command is present in an
  installed `charly` — **not because this PR changes `charly`, but because the capability and the pin are
  now both merged.** Before `#873` there was no build, installed or otherwise, in which it existed.

**The reviewer's alternative — "state plainly why a worktree build is the equivalent install" — is what
this section does, and it is the correct answer here rather than a paste from a released binary that would
